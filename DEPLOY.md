# Публичный запуск — чек-лист

Локально (`npm start` / `start.bat` / Docker без публикации наружу) приложение
безопасно по умолчанию: слушает только `127.0.0.1`. Этот файл — обязательный
чек-лист, когда сайт должен стать доступен из интернета (свой домен, не только
с этой машины). Источник: [ОТЧЁТ-фаза-3-безопасность-харденинг.md](ОТЧЁТ-фаза-3-безопасность-харденинг.md).

## 1. Reverse proxy + TLS — обязательно

Node-сервер сам TLS не умеет и не должен торчать в интернет напрямую. Перед
ним всегда должен стоять reverse proxy с HTTPS:

- **nginx** (есть встроенный rate-limit) — шаблон [deploy/nginx.conf](deploy/nginx.conf).
- **Caddy** (проще настроить, TLS сам себе выпускает) — шаблон [deploy/Caddyfile](deploy/Caddyfile).

Оба шаблона проксируют на `127.0.0.1:8765` и сами подставляют
`X-Forwarded-For`/`X-Real-IP` — клиент не может подделать эти заголовки,
проходя через прокси.

## 2. `.env` для публичного запуска

```
BIND_HOST=127.0.0.1
TRUST_PROXY=1
ORDER_RATE_MAX=8
```

- `BIND_HOST` остаётся `127.0.0.1` — наружу смотрит только proxy, не Node.
- `TRUST_PROXY=1` включайте **только** когда reverse proxy уже стоит и
  действительно подставляет IP (иначе клиент подменит заголовок и обойдёт
  лимиты логина/заказов/чата — сервер при старте печатает предупреждение,
  если флаг включён).
- `ORDER_RATE_MAX` — для одного локального покупателя 20 нормально; в
  публичном интернете опустите до 5–8, иначе недоброжелатель может быстро
  "выбрать" склад фейковыми заказами (отмена в админке возвращает остаток,
  но покупатели в этот момент видят "нет в наличии").

## 3. Docker

`docker-compose.yml` публикует порт **только на `127.0.0.1` хоста**
(`"127.0.0.1:8765:8765"`) — reverse proxy ставьте либо на хосте (шаблоны
выше), либо отдельным контейнером рядом, который тоже слушает `127.0.0.1`
контейнера/хоста для Node. Не меняйте это на `"8765:8765"` без proxy —
это равносильно `BIND_HOST=0.0.0.0` без reverse proxy.

## 4. Сессии админки

При смене `ADMIN_PASSWORD` в `.env` сервер при следующем запуске сам
сравнивает хеш с прошлым и, если пароль изменился, отзывает **все** активные
сессии (`DELETE FROM sessions`) — старый похищенный/забытый токен в этот
момент перестаёт работать. Отдельных действий не требуется, просто
перезапустите сервер после смены пароля.

## 5. Что сознательно не входит в этот чек-лист

Оставлено как приемлемый компромисс для масштаба (один доверенный
оператор — Эльмира/ассистент, низкая XSS-поверхность):

- HttpOnly-cookie + CSRF для админ-сессии (сейчас Bearer в `localStorage`);
- 2FA / отдельные роли админа;
- CAPTCHA на форме заказа/логина;
- integer/minor units вместо float для цен.

Если появится второй постоянный оператор, публичный спам-трафик или заметная
сумма в обороте — вернуться к этим пунктам (см. [ОТЧЁТ-фаза-3-безопасность-харденинг.md](ОТЧЁТ-фаза-3-безопасность-харденинг.md), раздел «Можно отложить»).
